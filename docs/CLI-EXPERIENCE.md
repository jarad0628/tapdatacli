# Tapdata CLI 交互体验草案

状态：目标交互设计，部分落地。2026-11-03 完成命令/数据源/表名 Tab 补全、数据库工作区提示、数据源状态与表结构/样例的终端格式化。更完整的多面板交互仍待迭代。2026-10-23 补充 AI 绑定、模型选择、初始化与斜杠命令体验。引擎按 tapdata-test 的直接连接器调用方式实现；终端单独开发，通过结构化协议调用引擎。

## 体验目标

技术栈建议为 TypeScript（Node.js）终端与 AI 层，加独立 Java Mini Engine。引擎按需启动且复用，准备期间保留输入和帮助；通过结构化事件展示实际就绪、进度和取消状态。引擎异常退出时保留终端会话，展示受影响任务及恢复入口。终端组件框架先通过中文输入、多行粘贴和滚动原型验证，具体进程协议见 [整体设计](./DESIGN.md#技术栈建议typescript--java)。

用户以自然语言提出任务，CLI 持续显示它理解了什么、正在做什么、需要补齐什么以及真实结果。连接、表、当前计划和运行任务具有明确身份；切换连接后不会误用上一个表，修改计划不会静默改变正在运行的任务。

自然语言是主入口；连接选择、参数表单、表格预览和计划操作使用终端组件辅助。自然语言流程不要求用户记住 PDK 类名或工具参数；JAR 路径和配置文件可用补全与表单提供，高级用户可直接输入原始命令。

## 首次启动：绑定 AI 后进入工作区

```text
$ tapdata

欢迎使用 Tapdata
选择 AI 接入方式：
  › Codex CLI         使用本机 codex
    Claude CLI        使用本机 claude
    自定义 API         API URL + API Key（中转站 / DeepSeek 等）
    稍后配置           先使用连接器和数据源命令
```

CLI 选项检测可执行文件和版本，允许更改路径；已登录则复用其认证入口，未登录则指引原生登录，返回后可重试检测。不要把“检测到命令”显示成“已经登录并可调用”。检测失败保留当前选择，可转 API 或先进入命令模式。

API 表单包含绑定名称、API URL、协议、遮挡的 API Key 和模型。优先显示可发现模型，接口不支持列举时允许手填；测试分别反馈网络 / 认证、模型响应及工具调用能力。失败不清空已填值。密钥不进入对话、命令历史或可复制诊断文本；表单直接提交本地凭据通道。

```text
✓ 已绑定 work-codex
✓ Tapdata 命令上下文已就绪
  引擎：首次使用数据能力时准备

AI: work-codex · 模型: <当前模型> · 数据源: 未选择
> 输入自然语言，或输入 / 查看命令
```

绑定完成只显示已实际完成的状态；初始化失败使用“AI 已绑定，Tapdata 上下文准备失败，可重试”，不能显示整体就绪。再次启动使用保存的绑定，不重复向导；提供 `/ai bind` 添加、`/ai use` 切换、`/ai status` 检查和 `/ai unbind` 移除本地绑定。

### 模型选择与原生能力

输入 `/model` 打开当前绑定可用的模型选择器，标明当前模型、可用设置与状态。推理强度等选项仅在适配器声明支持时展示；模型列表不可用可输入模型 ID，并在实际调用中验证。参数不支持时解释原因，不生成虚假的切换成功提示。

回答中切换模型时显示“当前回答结束后生效”，允许用户先中断再切换。跨绑定切换携带 Tapdata 工作区摘要并显示新会话，运行中的数据任务继续独立运行。当前 AI 不可用时仍能用 `/task status`、`/task stop` 和数据源命令。

CLI 特有且尚未映射的能力提供原生工具入口，进入和退出时明确提示终端控制权切换。Tapdata 自己的 `/connector`、`/datasource`、`/task` 由本地解析，避免与原生 CLI 的斜杠命令冲突；不解析或嵌套渲染另一个 TUI 的屏幕内容。

### init 与后台准备

`/init` 或 `tapdata init` 可显式准备缺失项；`--repair` 用于检查和修复 Tapdata 管理的资源。自动初始化只在需要时进行：本地目录和命令上下文可快速后台完成，引擎按需启动。需要输入的 provider / 凭据放在前台，已有值不重复询问。

耗时过程显示当前步骤和重试入口，保持输入区可用；依赖引擎的命令可以明确排队，帮助和 AI 配置无需等待。首次准备失败不能导致整个 CLI 无法进入。退出后重试复用已完成的初始化步骤。

## 斜杠命令与自然语言共用流程

当前 readline 原型用 Tab 提示命令、已保存的数据源、任务、连接器以及已加载表名；顶部显示数据库工作区操作入口，提示符在存在连接时显示连接数和已加载表数。`/datasource list`、`describe`、`load` 和 `sample` 使用紧凑表格与状态标签。后续交互升级应保留同一套命令语义，并在终端组件选型时重点验证中文输入法、多行粘贴和窄屏表现。

输入 `/` 显示命令分组；选中 `/connector`、`/datasource`、`/task` 显示子命令、参数提示和示例。补全基于本地命令定义、已装载 pdkId、连接名及可用任务，不依赖模型生成帮助。脚本命令与交互命令共享同一实现，具体语法见 [整体设计](./DESIGN.md#原始命令体系)。

自然语言产生的操作展示简短说明及可展开的等价原始命令。缺少参数优先用选择器 / 表单补齐；执行后展示真实工具反馈，AI 再解释结果。失败命令可以修改参数重试，重试范围清楚，不重放之前已经完成的整条工作流。

### /connector 面板

默认展示连接器名称、pdkId、版本、来源、装载状态和引用数，可选择 load / unload / update / list。

- load 支持粘贴或补全本地 JAR 路径；按需提供依赖目录。完成后突出显示提取到的 pdkId 和“用此连接器创建数据源”入口。
- update 展示旧 / 新版本及受影响引用；失败仍展示旧版本可用，现有任务版本不被替换。
- unload 被占用时展示具体数据源 / 任务，提供查看依赖的入口；不静默停止任务或删除连接配置。
- Maven 下载显示为后续规划，不在原型中伪装成已可使用的正式来源。

### /datasource 面板

list 展示连接名、连接器版本、最近测试结果和模型加载状态，测试与模型状态使用不同列。create 依据选择的 pdkId 展示配置字段，支持 JSON 文件和 key=value，敏感字段用遮挡输入；字段不全保留已有值继续补齐。

```text
> /connector load --jar ./connectors/mysql.jar
✓ 已装载 MySQL · pdkId: <实际返回值> · 版本: <实际返回值>

> /datasource create crm --pdk-id <返回的pdkId> --config ./crm.json
✓ 已创建 crm
  连接测试：未执行 · 模型：未加载

> /datasource test crm
✓ 展示连接器实际返回的检查项

> /datasource load crm
  正在发现表模型…
✓ 完成后显示真实表数量和加载时间
```

以上输出是交互示意，不代表当前已实现。自然语言“加载这个 JAR，创建 crm 并看看有哪些表”可串联同一组操作，AI 获得装载结果中的真实 pdkId；连接配置不足时补参，不猜测凭据。测试失败时就地提供 modify → test → load 的恢复路径。

load 表示元数据发现与缓存，不表示搬运业务数据。发现时间较长时返回可跟踪操作，展示已发现数量，不编造总量；成功替换缓存，失败保留旧数据并标注更新时间和 stale 状态。大量模型采用分页与搜索展示。

modify 展示脱敏变更与缓存失效状态；drop 明确说明删除的是本地连接定义。若连接被任务引用，列出依赖。用户已明确要求且依赖校验通过的操作直接执行；缺少对象或删除范围不明确时才补充询问。

### /task 面板预留

先保留候选的 create / modify / list / describe / start / stop / status / monitor / logs / stats / drop。菜单仅启用当前引擎已实现的操作，其余标注规划中。详细任务定义随后续需求更新，不能因 tapshell 有相同命令就展示为本地已经可执行。

## AI 上下文与执行的可见性

绑定状态区可以查看“Tapdata 上下文版本、注入状态、支持的命令组”。上下文包含命令说明和动态工作区引用；skill / hook 是适配方式，不要求用户手写提示词才能使用自然语言。连接器 load / update、datasource modify / load 等操作后刷新上下文。

首次绑定验收必须检查 AI 取得真实 pdkId、按配置要求补参、引用连接名并调用实际命令。仅输出帮助、建议用户自行执行，或只生成命令文本不算自然语言操作闭环。工具受权限限制时展示原始原因及可用下一步，保留请求与结果关联，避免重复执行。

## 终端布局与输入

采用可滚动的对话记录、紧凑任务摘要和底部输入区。普通问答保留自然阅读顺序，工具执行默认折叠为一行，可展开查看参数和结果。任务高频进度在固定摘要内更新，不逐条刷满对话。

输入区支持中文与输入法、中文宽字符、多行粘贴、光标编辑和历史召回。中文输入法确认候选不能误提交。长输出、终端缩放、窄屏和日志突发时，输入内容与光标保持稳定。提供可发现的快捷键提示；具体提交与换行组合在原型中验证后确定。

保留终端复制、滚动和文本可访问性。明确区分模型响应中、工具等待中、作业运行中和等待用户补充。长时间没有结果时显示已知阶段与耗时，不虚构百分比或预计完成时间。

## 核心交互流程

### 面向日常数据库工作的对话入口

用户不必先知道某项操作对应哪个命令，可以直接说：

```text
帮我找出 crm 里最近 7 天没有更新过的客户，按更新时间倒序看前 20 条
解释这条 SQL 为什么慢，先不要执行
把重复邮箱的客户找出来，告诉我会影响哪些记录
将订单表导出为 CSV，按月份拆分文件
把 crm.customer 的数据复制到测试库，email 列不要复制
```

CLI 先解析用户指向的数据源和对象，查询该连接器可用能力，再决定能直接读、需要补充条件，或生成待执行计划。回答应显示数据来源、筛选 / 排序 / 限制条件，以及样例是否截断。对写入、删除、DDL 或覆盖操作，展示实际对象和可获得的影响估算后再执行；用户在确认前可以改条件、选择连接或放弃计划。无法确定影响范围时直接说明“无法预估”，不能用猜测数字替代。

若连接器不支持所请求的能力，说明缺少的接口或权限，并提供仍可行的方案，例如“连接器支持读取但不支持更新；可以导出符合条件的记录，或先生成 SQL 供你在数据库客户端执行”。不应仅因为底层数据库通常支持某功能，就声称此连接器可用。

### 连接数据源

用户输入“连接一个 MySQL”，展示连接器所需字段并保留已填值。密码使用遮挡输入，仅向模型提供凭据引用。连接测试逐项展示网络、认证、权限等连接器实际返回的检查项；权限不足时允许修正后重试。

连接器不存在时展示可用能力及安装状态；安装过程和连接配置属于独立步骤。连接别名用于后续引用，状态栏显示当前连接。

### 查找与理解数据

“有哪些客户表”先检索元数据，再以可选择列表展示数据库、schema、表名和描述。重名表必须保留限定名。大量表支持搜索、分页和局部展开，不把所有 schema 塞进对话。

结构与样例分开展示。样例表格标明实际行数、截断列与读取限制；长值可展开。大整数、null、时间和二进制保留明确语义。采样默认不扫描整表，并依据已验证连接器能力实现读取限制。

### 计划与修改

“排除手机号，导出 CSV”生成简短计划：源表、目标路径、字段变更、读取模式和已有目标处理方式。用户可继续说“邮箱也不要”“改到另一个目录”，看到计划更新及变更摘要。

计划具有版本。运行绑定该版本，修改只影响新版本。参数完整且用户已明确要求执行的操作直接执行；意图不明或涉及覆盖、删除且缺少授权时，仅就具体缺失点询问，避免每一步机械确认。

### 执行期间继续对话

```text
你  把 customers 导出成 CSV，不要 phone

Tapdata  将 crm.customers 导出到 ./customers.csv，排除 phone。

  导出任务 #12 · 运行中
  已读取 128,000 行 · 已写出 127,000 行 · 8.2 秒
  当前阶段：写出 CSV

你  这个表有哪些时间字段？

Tapdata  created_at、updated_at。导出任务 #12 仍在运行。

> 输入消息…
```

运行任务与模型回复独立调度，查询是否可以并行由引擎判断；连接器不允许并发时提示排队。对同一个运行任务提出变更时，明确解释是否支持在线修改；首版可采用“停止旧任务后用新计划重跑”，先明确部分输出处理方式。

统计区分已读取、已处理、已确认写入和失败。没有可信总行数时显示计数与耗时。作业结束给出真实输出位置、记录数、耗时和未完成事项。

### 中断与取消

停止模型回答、取消工具请求、停止数据作业是不同操作。快捷键行为随当前焦点和运行状态显示提示，不能把停止生成显示为任务已停止。

取消任务后显示“正在停止”，直到引擎确认。取消超时继续显示实际未知或停止中状态。存在部分输出时，完成摘要说明路径、数量及能否继续；不默认宣称可恢复。

### 错误与恢复

优先展示任务阶段、影响和下一步，例如“认证失败，尚未读取数据，可以更新凭据后重试”。支持展开诊断信息，保留脱敏日志。

模型服务不可用时保留会话和任务状态，用户仍可查看、取消任务或用确定性命令操作。引擎退出时展示最后已知进度及状态未知，重新连接后核对真实状态。写入一部分后失败与完全未执行必须清楚区分。

会话恢复加载连接引用、计划和历史摘要；任务运行状态必须向引擎查询，不能用历史文本推断。会话恢复与任务断点恢复分别展示。

## Agent 与引擎之间的交互协议

第一版可使用本地 socket 加逐行 JSON，保证插件日志与协议隔离；最终传输方式按实现验证。无论传输方式如何，保持以下语义：

- 请求带 requestId；运行结果返回 jobId 与 planVersion。
- 事件带 jobId、sequence、timestamp、type 和结构化 payload；支持状态快照与重新订阅，CLI 据此恢复展示。
- 事件包含阶段变更、批次进度、警告、错误、取消确认与任务结束。每个任务具有唯一最终状态。
- 状态机为 queued → running → succeeded / failed，或 queued / running → cancelling → cancelled；停止失败不能报 cancelled。
- 高频计数事件可合并；状态变更、错误和结束事件不可丢失。日志与事件分流，数据批次留在 JVM 内。
- 连接测试返回检查项；元数据返回分页结果；采样返回限定大小的数据；后台任务返回句柄，避免阻塞整个聊天工具调用。

此协议同时服务 Agent、交互组件与脚本命令。UI 不解析连接器日志判断任务成功。

## 原型与验收

先用模拟引擎形成可运行终端原型，并明确标记模拟模式。需要覆盖的场景：

| 场景 | 可观察的验收结果 |
| --- | --- |
| 首次启动与跳过绑定 | 可选择 Codex / Claude / API，失败可重试，跳过后仍能用手动命令 |
| AI 绑定与模型切换 | 绑定真实可用，模型和可用参数来自适配器，切换不重复执行任务 |
| init 与自动初始化 | 可显式执行、重复执行、失败重试；后台进度不破坏输入 |
| 上下文注入 | AI 知道实际命令和当前 pdkId / 连接，执行结果能用于后续步骤 |
| 连接器管理 | JAR 路径可补全，版本 / pdkId 可见，带引用卸载有明确反馈 |
| 数据源管理 | JSON 和 key=value 均可用，create / modify / drop 语义清楚，test 与 load 状态分开 |
| 三种入口一致 | 自然语言、斜杠与脚本指向同一命令定义并返回一致结果 |
| 中文输入与多行粘贴 | 不误提交、不丢字，流式输出时输入区稳定 |
| 多轮修改计划 | 明确当前版本，执行参数与展示一致 |
| 长任务与并发对话 | 对话可继续，任务身份和状态不混淆 |
| 取消发生在写入期间 | 展示停止过程、真实最终状态和部分输出 |
| 模型断线 | 保留输入和会话，已运行任务可查看和取消 |
| 引擎退出与重连 | 区分最后已知状态与实时状态，重新核对任务 |
| 大量表与宽数据 | 可搜索、分页、截断、展开，终端仍可使用 |
| 非 TTY / 管道 | 提供稳定 JSON 或纯文本结果，不输出控制字符 |

随后以同一协议逐项替换为真实连接器能力。体验原型通过不代表引擎功能通过；真实数据验证需检查输出内容、失败行为和资源释放。


## 本地开发操作补充（2026-10-23）

自然语言能力增加宿主管理的 `local exec --cwd DIR --argv JSON_ARRAY [--timeout SECONDS]`，用于用户要求的文件检查、Maven/npm 编译和打包。Codex、Claude、API 共用此能力，provider 本身仍只生成经校验的命令提案。宿主展示命令与限量日志，回传实际退出码、输出尾部和完整日志路径；失败后由模型根据真实错误决定后续操作，不宣称成功。默认不经过 shell；继承当前用户权限和环境，不提供本地执行沙箱。提示词限定用户授权范围，文件和工具输出作为不可信数据。Ctrl+C 取消回答及本地进程，POSIX 下停止进程组；数据任务仍独立取消。完整日志保存为私有文件，本地命令参数不写交互历史。编译连接器优先选择所需模块及依赖，成功后重新 discover 用户指定的 dist 目录。
